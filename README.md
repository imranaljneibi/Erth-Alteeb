# إرث الطيب — إدارة المبيعات والمخزون

تطبيق عربي كامل يعمل بخادم Node.js وقاعدة SQLite على القرص، دون اعتماد على تخزين المتصفح لحفظ العمليات. الواجهة تتصل بالخادم وتستقبل إشعارات التغيير مباشرة، ثم تعيد حساب الأرقام من البيانات المحفوظة. لا يتضمن المشروع بيانات أعمال حقيقية أو كلمة مرور افتراضية.

## التشغيل

يتطلب Node.js 24 أو أحدث. لا توجد حزم npm خارجية لتثبيتها.

```bash
npm start
```

افتح `http://localhost:3000`، ثم أنشئ حساب المالك في شاشة الإعداد الأولى. اختر بريدًا وكلمة مرور قوية، ورأس المال والعملة. بعد ذلك تغلق إمكانية إنشاء حساب إضافي. استخدم كلمة مرور خاصة بهذا البرنامج.

```bash
npm test
npm run check
```

يمكن تغيير المنفذ ومسار البيانات بمتغيري `PORT` و`DB_PATH`. يبدأ الخادم افتراضيًا على `0.0.0.0`، ويجب حفظ مجلد قاعدة البيانات على قرص دائم. لا تنقل أو تحذف ملفات قاعدة البيانات أثناء التشغيل.

## الهاتف والكمبيوتر

كل جهاز يتصل بعنوان الخادم نفسه ويسجل الدخول بالحساب نفسه يحصل على البيانات نفسها. يستقبل التطبيق تحديثات SSE، ويعيد الاتصال تلقائيًا بعد انقطاع الشبكة. لا يعرض نجاحًا عند تعذر تأكيد الحفظ. يحمل كل إرسال من النموذج مفتاحًا يمنع تكرار العملية عند إعادة المحاولة من النموذج نفسه بعد انقطاع الاتصال، حتى بعد إعادة تشغيل الخادم. عند انقطاع الرد زامن البيانات وراجع السجل قبل فتح نموذج جديد. تعديل سجل قديم بينما عدله جهاز آخر يرفض برمز تعارض ويعرض القيم الحالية للمراجعة بدل الكتابة فوق التعديل الأحدث.

التطبيق المحلي ليس رابطًا عامًا منشورًا. للوصول خارج الجهاز المضيف يلزم نشر الخادم على استضافة تدعم Node.js وقرصًا دائمًا وHTTPS. لا يوجد مشروع Supabase مرتبط بهذه النسخة. ملفا `Dockerfile` و`compose.yaml` يجهزان تشغيل نسخة واحدة من الخادم مع مجلد بيانات دائم، خلف وكيل HTTPS. لا تشغّل عدة نسخ منفصلة على قواعد بيانات مختلفة.

عند النشر العام: فعّل `COOKIE_SECURE=true`، واجعل الخادم خلف HTTPS، واضبط `PUBLIC_ORIGIN` على عنوانه العام، وخصص `SETUP_TOKEN` سريًا للإعداد الأول أو أنشئ حساب المالك قبل كشف الخادم للإنترنت. عند استخدام رمز الإعداد يجب إدخاله في شاشة إنشاء الحساب. إعداد Docker المرفق يربط المنفذ بـ localhost ويحتاج وكيل HTTPS لفتح الوصول الخارجي. لا تعطّل حماية ملفات تعريف الارتباط في الاستضافة العامة. للتشغيل المحلي دون HTTPS استخدم `npm start` دون `COOKIE_SECURE`.

## الحسابات

- المبيعات = مجموع الكمية × سعر البيع لكل عملية ضمن الفترة.
- تكلفة البضاعة المباعة = مجموع الكمية × تكلفة الوحدة المثبتة في عملية البيع. تعديل تكلفة المنتج لاحقًا لا يعيد تسعير المبيعات القديمة.
- صافي الربح = المبيعات − تكلفة البضاعة المباعة − المصاريف.
- هامش الربح = صافي الربح ÷ المبيعات × 100؛ يعرض صفرًا عندما لا توجد مبيعات.
- المخزون الحالي = المخزون الأساسي للمنتج − كميات جميع المبيعات؛ لا يتأثر بفلتر التقارير. تعديل كمية البيع أو حذفها يعيد حسابه فورًا.
- المستحقات = قيمة جميع المبيعات − مجموع الدفعات المرتبطة بها. الدفعات لا تسجل إيرادًا جديدًا.
- المتبقي لاسترداد رأس المال = الأكبر بين صفر ورأس المال ناقص صافي الربح التراكمي. هذا مؤشر مبني على **الربح المحاسبي** ويشمل المبيعات غير المحصلة، وليس بيان تدفق نقدي. الخسائر ترفع المبلغ المطلوب استرداده.
- ملخص اليوم يستخدم تاريخ دبي الفعلي. الأسبوع يبدأ الاثنين وينتهي الأحد. الشهر والسنة فترات تقويمية حسب التاريخ المرجعي المحدد.
- تقبل تواريخ الأعمال بين 1900 و2100. تغيير العملة بعد تسجيل عمليات مرفوض لحماية معنى الأرقام؛ لا يوجد تحويل أسعار صرف.
- المبالغ تخزن بأجزاء العملة الصحيحة لتجنب أخطاء الفاصلة العائمة. الكميات أعداد صحيحة من وحدة المنتج المحددة؛ الأجزاء العشرية للوزن غير مدعومة.

لا تسجل تكلفة شراء نفس المخزون مرة أخرى كمصروف تشغيلي إذا كانت مضمنة في تكلفة الوحدة، حتى لا تخصم التكلفة مرتين. يمكن تحرير تكلفة البيع التاريخية صراحة إذا كانت هي المراد تصحيحها.

## الحفظ والنسخ والاستعادة

زر حفظ أي عملية يثبت التغيير وسجل التدقيق في معاملة واحدة، ثم يحدّث الشاشات المتصلة. الكتابة داخل نموذج دون الضغط على حفظ لا تنشئ عملية مالية. رسائل النجاح لا تظهر إلا بعد رد الخادم بنجاح.

من الإعدادات صدّر نسخة JSON واحتفظ بها في مكان خاص؛ فهي تحتوي بيانات الأعمال. الاستعادة تتحقق من صيغة الملف والمراجع والكميات والمبالغ وكلمة مرور المالك قبل استبدال بيانات الأعمال. تبقى بيانات الدخول وسجل التدقيق الحالي محفوظين، وتسجل عملية الاستعادة كتعديل جديد. سجل التعديلات المصدّر مرجع أرشيفي ولا يستبدل السجل الحالي عند الاستعادة. النسخة ليست نسخة من كلمات المرور أو الجلسات. احتفظ بنسخة خارج جهاز الخادم قبل الاستعادة. الحد الأقصى لطلب الاستعادة 25 ميبيبايت ولعدد سجلات الأعمال المستوردة 100 ألف؛ تُرفض النسخة غير المطابقة دون تغيير البيانات.

يمكن تعديل العمليات السابقة وتغيير تواريخها. يمنع الخادم بيع مخزون غير متاح، أو دفع مبلغ أكبر من قيمة البيع، أو تخفيض قيمة بيع إلى أقل من دفعاته. احذف أو صحح الدفعات أولًا عند الحاجة. حذف البيع يحذف دفعاته ويعيد مخزونه، ويسجل الأثر. حذف منتج له مبيعات مرفوض للحفاظ على الترابط.

## الشعار

الملف `public/logo.png` هو الصورة الأصلية المتاحة باسم «إرث الطيب: Patterned Arabic Logo.png»، دون إعادة رسم أو تغيير الكتابة. لم تتوفر صورة مرفقة مباشرة مع الطلب، لذلك هذه الصورة بديل مؤقت من ملفات المستخدم حتى تأكيد الأصل المطلوب. العرض الدائري يتم بقص CSS وإخفاء الحواف الخارجية فقط؛ ويظهر في الدخول ورأس الصفحة والقائمة الجانبية والطباعة. استبدال ملف الشعار يحتاج مراجعة مقدار القص إذا كانت أبعاد الأصل الجديد مختلفة.

## نطاق النسخة

حساب مالك واحد، عملة واحدة قابلة للاختيار، منتجات وكميات صحيحة، عملية بيع لمنتج واحد ويمكن تسجيل عمليات متعددة للفاتورة، مصروفات ودفعات وسجل تعديلات وتقارير ونسخ احتياطي. لا توجد ضرائب أو ربط بنكي أو بوابة دفع أو إرسال تنبيهات خارج التطبيق. تنبيهات انخفاض المخزون والمستحقات داخل التطبيق.

هذه النسخة شُغلت للاختبار في بيئة العمل، ولم تُنشر بعد على رابط إنترنت. ملف الاختبارات يتحقق من الحسابات على قاعدة بيانات منفصلة؛ لا ينشئ بيانات تجريبية في حساب المستخدم.
